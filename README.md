# hangke-ide

面向教学场景的 AI 代码编辑器，分发为 **Windows 免安装版**，覆盖 **Windows 7 SP1 ~ Windows 10**（32/64 位）。

## 关键约束

| 项 | 取值 | 原因 |
|---|---|---|
| Electron | **22.3.27**（锁定） | 22.x 是最后一个支持 Win7 的版本，23 起要求 Win10 1809+ |
| 渲染目标 | Chrome 108 | Electron 22 内置 Chromium |
| 主进程目标 | Node 16 | Electron 22 内置 Node 16.17.1（无全局 fetch） |
| 原生模块 | **禁止引入** | ABI 110，预编译包不可用 |

## 打包方式

**只通过 GitHub Actions 打包**，开发环境不做 Windows 打包（`npm run dist:win` 会直接拒绝执行）。

产物（免安装 zip，x64 + ia32）：

```
hangkeIDE-<version>-win7-win10-x64.zip
hangkeIDE-<version>-win7-win10-ia32.zip
```

> **zip 里套了一层同名文件夹**，解压出来是 `hangkeIDE-<version>-win7-win10-x64/`
> 一个目录，而不是把 exe / dll / locales 摊在下载目录里。
> 实现见 `scripts/zip-wrap-folder.mjs`：electron-builder 24.x 的 zip 目标是
> 平铺的（`ArchiveTarget` 在 Windows 上写死 `withoutDir=true`，配置里改不了），
> 所以挂在 `afterAllArtifactBuild` 钩子上，**直接改 zip 字节**把顶层条目
> 挪进那个目录 —— 压缩数据原样搬运，CRC / 时间戳 / 压缩方法 / UTF-8 标志位
> 全都不变（中文文件名不会变乱码），97 MB 的包毫秒级完成。
>
> ⚠️ **第一版是调外部 `7za rn`，在 CI 上挂了**，教训写在这里：
> 那个写法依赖两件开发机上测不到的事 —— 一是外部 7za 的版本行为
> （开发机 Linux p7zip 16.02、runner Windows 7-Zip 21.07，不是同一个程序，
> 而本项目**只出 Windows 包**，拿 Linux 的 7za 验证等于没验证）；
> 二是**它的文本输出**（按控制台代码页输出文件名，英文 runner 表示不了
> 「使用说明.txt」，读回乱码再喂回 `rn` 就匹配不到，而退出码仍是 0 ——
> 静默什么都没做）。现在纯 Node 实现，不依赖任何外部程序、不解析任何文本，
> 两边行为完全一致。护栏见 `scripts/check-zip-wrap.mjs`。

> Windows 版本不是打包维度。同一份包在 Win7 SP1 / Win8 / Win10 上都能跑，
> 系统差异在启动时自适应（Win7/8 走软件渲染，Win10 走硬件加速）。

### 产物从哪拿

| 位置 | 在哪 | 说明 |
|---|---|---|
| **Releases 页**（推荐）| 仓库 → Releases | `latest` 是 main 的滚动构建（prerelease）；推 `v*` tag 生成正式 Release |
| Artifacts | 工作流**运行页**（不是任务日志页）底部 | 带自检报告，默认 90 天后过期 |

> 两个常见困惑：
> 1. **任务日志页看不到 Artifacts**，必须点进工作流的运行页，在最下方。
> 2. 构建成功**不会自动产生 Release**（除非推 tag），这是刻意的：Release 只从 tag 或滚动 `latest` 来。

## 本地开发

```bash
npm ci
npm run dev        # 开发模式（Vite HMR）
npm run typecheck  # 类型检查（主进程 + 渲染层，两份 tsconfig）
npm run build      # 构建（会先跑下面 5 个离线校验）
npm run smoke      # 无头启动自检（Linux 需 xvfb，其他平台会直接弹窗口）

# 离线校验：全是纯逻辑，几毫秒跑完，不需要窗口/文件系统/AI
npm run check:node16     # Node 16 API 边界（主进程跑在 Electron 22 的 Node 16 上）
npm run check:watch      # 文件监视的时序
npm run check:editmatch  # editFile 的宽容匹配级联（4 级）
npm run check:argguard   # 工具参数截断守卫（4 种流形态的区分）
npm run check:cmdsafety  # 命令行引号 / PATH 防投毒 / 工作区安全校验
npm run check:budget     # 上下文预算与压缩阈值

# 自检支持追加参数，用于在本地复现 CI 里那几次不同配置的运行
npm run smoke -- --capability-profile=win7   # 强制 Win7 工具能力档
npm run smoke -- --software --self-test-out=t.json
```

> 开发态的用户数据目录是 **`hangkeIDE-dev`**，与打包版的 `hangkeIDE` 分开。
> 这样 `npm run dev` 不会和本机已解压的打包版抢单实例锁，也不会写坏真实配置。
> 启动日志会打印实际目录。

### 只跑 Vite（Electron 窗口起不来时用）

`npm run dev` 会同时拉起 Vite 与 Electron 窗口。两者是**同生共死**的 ——
窗口如果在受限环境里崩掉（`chrome-sandbox` 权限不对、容器里 futex 不可用），
Vite 也跟着退出，表现就是「5173 打不开」。

这时可以只跑渲染层：

```bash
npx vite --config vite.preview.config.ts
```

浏览器打开 5173 就能看界面 —— `dev-api-stub.ts` 会接管 `window.api`
（内存文件系统 + 模拟 AI 流），文件树、对话、设置页都能点。
代价是没有真实文件系统与 IPC。

> 另一种情况：本机残留着**上次没退干净的 electron 进程**，它占着
> `~/.config/hangkeIDE-dev` 的单实例锁，会让新启动的窗口直接退出。
> `ps -eo pid,cmd | grep electron` 看一下，有残留就 kill 掉。

### dev server

| 项 | 值 |
|---|---|
| 地址 | `http://0.0.0.0:5173/`（绑所有网卡，局域网可访问）|
| 端口 | `5173`；`strictPort` 打开，被占时直接报错，不会悄悄换端口 |

只想本机访问：把 `electron.vite.config.ts` 里 `renderer.server.host` 改回 `'127.0.0.1'`。

**不要用普通浏览器直接打开 5173** —— 渲染进程依赖 preload 注入的 `window.api`，
缺了它 `App.tsx` 会直接报错白屏，5173 只能由 Electron 加载。

Linux 容器 / root 环境下 Electron 起不来（`chrome-sandbox` 非 setuid-root），改用
`npx electron-vite dev --noSandbox`。

## AI 工具能力（按系统分层）

AI 能对文件做什么，由**两层**共同决定：

| 层 | 来源 | 说明 |
|---|---|---|
| 设置 | `config.capability`，在「设置 → 工具能力」里改 | 你**愿意**放开到哪（自动 / 保守 / 全开） |
| 探测 | 启动时读系统版本与解释器，只读 | 这台机器**实际**能做到哪 |

最终生效 = 设置上限 ∩ 本机探测 − 逐个关掉的项。改完保存立即生效，不用重启。

文件类工具 8 个（读取 / 写入 / 替换一处 / 替换多处 / 列出目录 /
**查找文件（Glob）** / **搜索内容（Grep）** / 撤销修改），
命令类工具 4 个（执行命令 / 后台任务 / 查询任务 / 终止任务），
记忆与会话工具 4 个（翻归档会话 / 读会话记录 / 读记忆 / 记一笔），
技能工具 2 个（查看技能 / 读取技能）。

**Win7 与 Windows 10/11 都是 18 个工具**，同一份包、同一套代码。
其中命令类那 4 个要看本机探测（Windows 上找到 cmd.exe 才启用），
另外 14 个不依赖任何外部程序，两档都有。

> 这里改过一次判断。以前 Win7 分支**直接写死**「不启用命令执行」，
> 理由是「Win7 裸机只有 cmd.exe，PowerShell 要装 WMF 升级才有 5.1」——
> 那个理由站不住：**cmd.exe 在所有 Windows 上都有**，而 python / node
> 装好后会把路径写进 PATH，`cmd` 里直接敲 `python hello.py` 就能跑，
> 根本不需要 PowerShell。当时的代码甚至没去查解释器在不在，
> 代价是 Win7 用户白白少掉 4 个工具。
>
> 现在统一「探测到 cmd 就启用」。Win11 走同一条路径，但不在承诺支持范围内
> —— 详见 `docs/技术框架方案.md` 的支持矩阵。

门控作用在**发给模型的工具表**上，而不是界面上的按钮显隐：
模型看不到的工具就不会去调，省掉一整轮白跑的 token。

`--capability-profile=<tier>` 可以强制按某个系统等级计算能力集。
CI 会跑两次自检（默认档 + Win7 档）并断言**两档的工具集完全相同** ——
哪天又有人给 Win7 加回特殊分支，这条会立刻红。

### 执行命令类工具

四个：`执行命令`、`后台任务`、`查询任务`、`终止任务`。它们的存在意义是
「AI 能自己跑一下看看」，而不是「把终端搬进编辑器」。几个关键取舍：

- **跑的是 cmd，不是 PowerShell，也不是 Bash**。工具名叫 `RunCommand`
  而不是 `Bash`：叫 `Bash` 会让人以为 `&&`、`$VAR`、管道都能照搬，实际上不是。
  选 cmd 而不是 PowerShell 是因为**它在所有 Windows 上都有**，
  而 PowerShell 的版本差异（Win7 自带 2.0、现代语法要 5.1）反而是负担。
- **命令写进临时 `.cmd` 文件再执行**，而不是 `cmd /c "命令"`。三个坑一次避开：
  引号转义（Node 是 C 运行时那套、cmd 是另一套）、`%VAR%` 在解析阶段被提前展开、
  命令行 32767 字符上限。临时文件在执行结束后删除，启动时还会扫一次残留。
- **命令必须用英文写**。中文 Windows 的控制台对非 ASCII 字符处理不统一，
  中文命令容易解析失败。要处理中文内容请写在脚本文件里（如 python 源码），
  再用英文命令跑那个文件 —— 工具描述里就是这么约定给模型看的。
- **输出编码在脚本前先切成 UTF-8**（`chcp 65001`）。中文 Windows 的 cmd
  默认代码页是 936（GBK），而**被执行的程序自己会输出中文**
  （学生 `print("你好")`），只约定「命令用英文」解决不了这一半。
  Node 按 UTF-8 解字节就是满屏乱码，学生会以为是命令跑错了。
  收字节时用 `StringDecoder` 而不是 `chunk.toString()`，否则一个汉字被切在两个 chunk 之间就变成问号。
- **超时默认 30 秒，上限 5 分钟**，到点用 `taskkill /PID <pid> /T /F` 杀**整棵进程树**。
  顺序不能反：先 `child.kill()` 把 cmd 干掉的话，它启动的 `python.exe`
  就找不到爹了，`/T` 遍历不到，反而留下一堆占着端口与 CPU 的孤儿进程。
- **长命令走 `jobRun`**，立刻返回任务号，之后用 `jobPoll` 查。
  任务只活在主进程内存里（不落盘），并发上限 4 个，单个硬上限 30 分钟，
  关窗口时全部终止 —— 否则学生关掉编辑器后 `node.exe` 会继续占着端口，
  下次启动就变成「端口被占用」这种完全查不到原因的故障。
- **工作目录默认项目根目录，且必须在项目内**。命令本身当然能 `cd ..`，
  但默认落在项目里能让绝大多数情况不需额外参数。
- **输出有上限**（单次 6 万字符，回灌给模型前再裁到 1.2 万，留头尾）。
  跑一次构建可能吐几十万行，全塞进上下文既烧 token 也淹掉真正的报错。

**两件在真机上才能验的事**（见 `docs/多系统-测试清单.md`）：中文输出的编码是否正常、
杀软会不会拦子进程（校园机器上这一条会表现为「偶发失败」，很难排查）。

### 流式请求的超时：停顿判定，不是「一轮 N 秒」

一次提问是一个**工具循环**：模型调工具 → 主进程执行 → 把结果回灌 → 再发一轮，
最多 8 轮。每一轮都是一次独立的 HTTP 往返。

这里踩过一个坑，用户看到的现象是「AI 明明在输出，却因为 120s 的限制结束了」，
以及「最后改代码的时候因为超时被中断了」。根因是那一轮写死了一个
`setTimeout(120_000)`：它算的是**一次往返的总时长**，而不是「多久没动静才算卡死」。

计时器起于请求发出、清于这一轮结束，所以它覆盖的是**整次往返**：
建连 + 等首字 + 模型输出（正文 / 思维链 / 工具调用参数）。
每轮确实都重新计时 —— 问题不在重置，而在于每轮给的是**总时长上限**而非空闲上限：
只要这一轮墙钟超过 120 秒就砍，跟期间有没有在吐字无关。于是：

- 模型连续输出超过 2 分钟（长代码、长解释、推理模型的长思维链）**必然被砍**，
  哪怕那一刻分片还在源源不断地到；
- 要调 `editFile` 的那一轮，模型得先把思维链与正文吐完、再分片吐出工具调用参数。
  推理模型「想得久」很常见，整个往返超过 120 秒时，**参数还没吐完就被掐断** ——
  表现就是「正要改代码，突然超时结束了」。

（工具**执行**本身不在计时范围内：那时这一轮已经 settle、表已撤。
超时文案也有同样的毛病：一律写「请检查网络或中转站状态」，
而真实原因往往是「这个模型就是慢」，用户按提示去查中转站是白折腾。）

现在改成**停顿看门狗**（`src/main/stream-watchdog.ts`）：

| 计时器 | 值 | 重置条件 | 防的是 |
|---|---|---|---|
| 停顿 | 5 分钟 | **每收到一片数据** | 上游半死不活（连接在、一个字节都不发） |
| 单轮硬上限 | 15 分钟 | 不重置 | 中转站一直发保活注释、模型永远不答 |

- **收到任意字节就算「活着」**，不看这些字节解析出了什么。保活注释（SSE 的
  `: keep-alive`）、空 `choices`、usage 块全都重置计时器 —— 判断依据是
  「这条连接还在动吗」，而不是「有没有解析出正文」。
- **工具执行不在计时范围内**。模型给出 `tool_calls` 时这一轮就结束了，
  `settle()` 停表；工具跑完开下一轮才重新起表。所以跑一个 5 分钟的
  `runCommand` 不会吃掉下一轮的预算。
- 停顿阈值**不能设小**：HTTP 响应头通常要等模型吐出第一个 token 才发，
  所以「建连阶段」和「等首字」在时间上分不开，大上下文 + 慢模型时
  几十秒不出第一个字是正常的，30 秒那种值会把正常请求误杀。
- 单轮硬上限**兜的是停顿看门狗自己的漏洞**：中转站如果一直发保活注释、
  模型却永远不答，停顿计时器会被无限重置、界面永远转圈。
- 超时文案**分两种原因**写。原来一律是「请检查网络或中转站状态」，
  对「模型太慢」这种真实情况是误导 —— 用户会去查自己的网络，而问题不在那里。

`scripts/check-idle-timeout.mjs` 是这道行为的护栏：光把常量改大不算修好，
如果 `data` 回调里没有重置，那仍然是一个「每轮固定 N 分钟」的定时炸弹，
所以护栏同时断言「阈值够大」「data 回调里调了 progress()」「一轮结束时停表」。
这类 bug 在开发机上极难复现（要模型恰好输出满两分钟），只能靠静态断言钉住。

## 界面结构

两栏：

| 栏 | 管什么 | 关键文件 |
|---|---|---|
| 左侧栏 | 上半：产品标识 / 新对话·Skills·MCP / 工作空间 / 最近会话<br>下半：当前项目的文件树（可折叠） | `components/Sidebar.tsx`、`components/FileTree.tsx` |
| 内容区 | 横向分成**编辑器（左）**与**对话（右）**，中间是竖向可拖拽分割条 | `components/EditorPane.tsx`、`components/AiPanel.tsx` |

### 为什么是「编辑器在左、对话在右」

和 Cursor / Windsurf 一致：写代码时视线在左边，提问是**间歇动作**，放右栏不挡住代码。
反过来把对话放左边，每次提问都要把视线拉回最左侧、代码被推到右边，反而更累。

对话栏可以整体收起（顶栏那个面板按钮），收起后编辑器接管全部宽度。
收起用的是 `data-chat-closed` 属性 + `display:none`，不是条件渲染 ——
保留 DOM 才能留住输入草稿与滚动位置。

### 文件树为什么并进左侧栏

它和「工作区 / 最近会话」本来就是一类的：都是「我在哪个项目、项目里有什么」。
放同一栏符合直觉，也给对话栏腾出了完整的右侧空间。
左侧栏由此分成两个独立滚动的区段：

- `.sidenav-top` —— 动作键与两个列表，内容长了只滚这里
- `.nav-group-tree` —— 文件树，`flex:1 + min-height:0` 吃掉剩余高度、自己滚

这两段必须分开滚。以前整个侧栏是一块 `overflow-y:auto`，
文件树嵌进来后就会出现「文件多了把侧栏整个推长，而文件树自己那一段反而没滚动条」。

### 分割条的一个坑

竖向分割条**不能占布局宽度**。两侧宽度加起来已经是 100%
（`--split` 与 `1 - --split`），分割条如果再要 9px，它就会因为「没地方放」
被挤到容器最右边缘 —— 实测错位 454px。

解法：`width: 9px` 配 `margin: 0 -4.5px`，正负抵消后布局宽度为 0，
9px 的命中区横跨在接缝上，视觉上仍是一条 1px 竖线。

另外 DOM 顺序也必须是「编辑器 → 分割条 → 对话」。放到最后同样会被挤到最右边，
位置是由顺序决定的，光靠 CSS 救不回来。

### AI 改完文件，编辑器必须立刻看到

这是 AI 编辑器里最不能缺的一环。原来的实现里，AI 调用工具改了磁盘上的文件，
编辑器却还在显示内存里的旧副本 —— 学生看到「AI 说改好了，但代码没变」，
这种不一致足以让人完全失去信任。

修复分两半：

**主进程：`main/watcher.ts`**

用原生 `fs.watch(root, { recursive: true })` 监视工作区，改动推给渲染层。

- **不引 chokidar**：它在 Win7 上会退回轮询模式（`fs.watchFile`），50ms 一轮地 stat
  整棵目录树，机械盘上直接变成 100% 占用。`fs.watch` 在 Windows 上底层是
  `ReadDirectoryChangesW`，是真正的内核事件，零轮询开销 —— 对教室里的老机器
  这是唯一可接受的选择。
- **工具写入要标记来源**。`file-tools.ts` 在写盘前后调 `markToolWrite()`，
  事件里就带上 `origin: 'ai'`；否则编辑器分不清「AI 改的」与「别人改的」，
  只能一律弹提示，那就太吵了。
- **debounce 120ms**。一次写入通常触发多次事件（write + rename），需要合并。

**渲染层：`store.handleFileChanged()`**

按三种情况分别处理，因为「文件变了」在三处的正确反应完全不同：

| 情况 | 处理 |
|---|---|
| 没在编辑器打开 | 只记日志，不打扰 |
| 打开了、本地无未保存改动 | 静默重载，AI 改的标上「AI 修改」 |
| 打开了、本地有未保存改动 | **绝不覆盖**，只警告，由学生决定 |

第三条是关键：AI 改了文件而学生手里有没保存的编辑时，把磁盘内容盖上去
等于把学生刚写的代码删了。宁可保留冲突让学生选。

### 撤销 AI 的改动

`tools/snapshot.ts` 在每次写盘前存一份原文（跨重启保留）。两个入口：

- **编辑器内的横幅**：AI 改过的文件顶上会显示「AI 修改了 xxx」+「撤销这次修改」/「保留」
- **设置 → 修改历史**：列出当前项目所有可撤销记录（文件名 / 时间 / 来源 / 行数差）

手动保存（Ctrl+S）也会记一条快照。不记的话会有个难查的问题：
AI 改完 → 学生自己又存了一次 → 按撤销时退到 AI 改之前，学生刚写的东西凭空消失。

`listSnapshots()` **只返回当前工作区内的记录**。撤销记录是跨项目累积的，
把别的项目的文件列出来，学生按一下会改到另一个项目的代码，这在教学场景里很难解释。

### 会话恢复

重启后自动恢复上次打开的标签、激活项、每个文件的光标位置、以及分割比例，
存在 `config.json` 的 `editorSession` 里。

三个细节：

- **只存路径，不存内容**。内容是磁盘上的真实状态，缓存一份下来就会和磁盘分叉，
  下次启动反而显示旧代码。
- **落盘前过滤已不存在的路径**（`editorSessionSet`）。工作区可能在关机期间被移动或删除，
  照单全开会在界面上弹一排「打开失败」。
- **防抖 600ms + 关窗前 flush**。开关标签、移光标都会触发保存，太频繁；
  但直接关窗会丢掉最后几百毫秒 —— 而「刚打开一个文件就关掉应用」恰好很常见。

### 分割条的拖拽实现

左右可拖拽，键盘也能调（聚焦后用 ←/→ 步进 2%，Shift 加速到 10%，Home/End 到两端），
双击复位到 62%。（早先顶栏还有「改 / 均 / 问」三个预设按钮，已经去掉：
分割条本身就能拖、键盘也能调，三个按钮占着顶栏位置却只覆盖三个点。）

实现在 `hooks/useSplitter.ts`（支持两个方向，用 `axis` 参数切换），两个关键点：

- **拖动期间不 setState**。`pointermove` 能到 60~120Hz，每帧触发 React 重渲染会让
  Monaco 明显卡顿。所以拖动时只改 `documentElement` 上的 `--split` CSS 变量
  （不触发渲染），松手才提交一次状态。
- **用 Pointer Events + `setPointerCapture`**，不是 mouse 事件。这让指针跑到分割条
  外面（甚至窗口外）仍能继续收事件 —— 鼠标拖拽最容易在这里断掉。触摸也走同一条路径。

`--split` 的语义是**左侧（编辑器）占内容区的比例**。比例只存比值不存像素，
窗口缩放时按比例跟随。上下限是 `SPLIT_MIN` / `SPLIT_MAX`（0.28~0.78），
**界面与落盘共用同一组常量**（`shared/types.ts`）——
以前界面写 0.28~0.78、落盘夹 0.2~0.9，拖到中间地带会出现
「当次会话被夹住、重启后又原样读回来」的不一致。

### 空态（欢迎页）

火箭图标 + 「{时段}好，今天想从哪里开始？」+ 三张横排入口卡（解读项目 / 修复问题 / 头脑风暴），
下方是输入框与工具栏。

- **三张卡无论是否配置模型都显示**。它们本身就是「这个软件能干什么」的说明书，
  没配置时恰好是最需要它的时候；没配置时点击引导到设置页，而不是把卡片藏起来。
- **问候语按当前时段变**（早上好 / 下午好 / 晚上好），固定一句「你好」会显得很假。
- 输入框下方工具栏里的图片 / 附件 / 截图 / 配色 / Git 入口**置灰并标注「暂未支持」**。
  保留占位是为了让工具栏宽度稳定，以后接上功能时不会把右侧发送键挤走。
  点了没反应比明确说「还没做」更让人困惑。

### 文件树右键菜单

预览文件 / 新建文件 / 新建文件夹 / 重命名 / 移动到… / 删除 / 显示隐藏文件 /
复制路径 / 打开所在目录 / 插入引用 / 排序 / 刷新。

几个刻意的取舍：

- **预览文件**只对 `.html` 生效，走系统浏览器。实现上会起一个只绑 `127.0.0.1` 的临时静态服务
  把工作区当根目录 —— 直接给浏览器 `file://` 的话，`./src/main.js` 这类相对路径会被
  同源策略拦掉，学生看到的是「没样式也没反应」的页面。
- **删除**走系统回收站（`shell.trashItem`），不是 `rm`。误删能捞回来，这在教学场景里很重要。
  （早先的实现是往工作区里的 `.trash` 目录 rename。换掉是因为那个目录被放进
  忽略列表、文件树里看不见 —— 学生误删之后既看不到也拿不回来，等于物理删除但还占着磁盘。）
- **移动**有两条等价路径：树上直接拖拽（拖到目标文件夹上），或右键「移动到…」。
  两者最终都调同一个 `store.moveEntry`，不存在两套逻辑。拖拽是主路径，
  弹层是备选（目标在折叠的深层目录里、或鼠标拖不稳时用）。
  目标重名会**报错而不是覆盖**，跨盘会自动回退成「复制 + 删除」。
- **显示隐藏文件**是开关，写进 `config.explorer.showHidden`。`node_modules` / `.git` 之类
  无论开关如何都不列 —— 一次 `readdir` 几万条，Win7 机械盘上会直接卡死。
- **插入引用**不把路径拼进输入框文本，而是挂成输入框上方的胶囊。
  拼进输入框的话，学生想删掉一个引用得手动选中一大段路径。
- 不适用的项（比如没选中文件时的「重命名」）**置灰而不是隐藏**，菜单位置稳定才好找。

### 会话记录：索引与正文分开放

| 位置 | 存什么 | 上限 |
|---|---|---|
| `config.json` → `recentSessions` | 索引：id / 标题 / 工作区 / 时间 / 条数 | 20 条 |
| `userData/sessions/<id>.json` | 正文：消息列表 | 200 条 / 单条 20 万字符 |

分开的理由：左侧列表每次启动都要整份读，索引必须小；正文只有点开某条会话时才读，
几 MB 也无所谓。

**正文是整份覆写，不是追加**。写 `.tmp` 再 `rename` —— `rename` 在同一文件系统内是原子的，
所以要么读到旧的完整文件，要么读到新的完整文件，不存在中间态。
直接 `writeFile` 覆盖的话，写到一半断电就会留下截断的 JSON；
而 jsonl 追加写到一半会留下半行坏数据，还得写恢复逻辑。

**落盘有 400ms 防抖**，而且只在「一轮回答结束」和「用户主动停止」两个时刻触发。
流式期间每来一个 token 就写盘的话，一轮回答要写几百次几 MB 的文件。

**流式的中间态不落盘**：`items` 是渲染态（带 usage / tools），`messages` 是持久化态
（只有 role / text / at）。重建历史时不会带出上一轮的 token 数 —— 那些数字显示在旧气泡上
会让人误以为是当前的。

**气泡正文渲染前会做一次换行清理**（`shared/chat-text.ts`）：一次带工具的回答是
好几轮拼起来的，每轮正文模型都会带一两个换行，不清理就是「每执行一次工具，
气泡就多一片空白」，答案被越推越远。规则是**只压连续空行**（3 个以上压成 2 个，
保留一个空行的分段效果）、**只动行尾**（行首缩进是代码，动了就把 AI 给的代码改坏了，
而这个结果会存进会话记录）、首尾空行去掉、CRLF 统一。
纯函数且幂等，显示路径与落盘路径都能安全调用，测试在 `scripts/check-chat-text.mjs`。

`工作空间` 与 `会话` 都落在 `config.json`，关掉应用再打开还在。

### 页面预览

右键 HTML → 「预览文件」，会用系统默认浏览器打开它。
**保存或 AI 改完会自动刷新**（那是浏览器自己的刷新，不是应用内的面板）。

- **在系统浏览器里打开，不用应用内 iframe**。曾经内容区右侧有一个内嵌
  预览栏，已删除：编辑器 + 对话这两栏加起来正好是 100%，预览作为第三栏
  必须从 `--split` 里再切一刀（`--preview-share`），窄屏下对话栏会被挤到
  只剩十几个百分点 —— 而学生真正需要的是「用我平时那个浏览器看」。
- **不能直接把 `file://` 丢给浏览器**：页面里的 `./style.css`、`./main.js`
  会被同源策略拦掉，学生看到的是「没样式也没反应」的页面，
  比不打开更让人困惑。所以主进程会起一个**只绑 `127.0.0.1`** 的临时
  静态服务，把工作区当根目录，退出时关掉。

### 图片输入

模型支持多模态时可以粘贴截图（`Ctrl+V`）或点工具条的「图片」选图。

- **粘贴是主路径**。学生用 `Win+Shift+S` / QQ / 微信截完图直接贴进来 ——
  他们本来就这么发消息，不用学新操作。不做内置截屏正是因为这个习惯
  已经覆盖了绝大多数场景。
- **发送前压到长边 1568px 的 JPEG**。手机截图动辄两三 MB，原图直发会让
  token 消耗是压缩后的十几倍，上传也慢到学生以为卡死。
  压缩后一张截图通常 100~200 KB。
- **先铺白底再画**。JPEG 没有透明通道，带透明的 PNG 直接转会变成**黑底**，
  看起来像图坏了。
- **只在最后这一轮带图**，历史消息只发文本。base64 有几 MB，
  每轮重发会让同一张图被计费十几次，部分中转站还会因请求体过大直接 413。
- **开关是手动的**（设置 → AI 模型）。「这个模型能不能看图」中转站的
  `/models` 不会说，只能从模型名猜，而猜错的代价不对称：
  勾了但不支持 → 整个请求被拒；不勾但支持 → 只是用不上图片，别的都在。

### HTTPS 证书校验（设置 → AI 模型）

**默认不校验**。这不是图省事，而是目标平台决定的：

- Win7 的根证书库**随系统更新**，而 Win7 早已停止主流支持，
  新的根 CA **装不进去** —— 典型的就是 Let's Encrypt 的 ISRG Root X1
  那一批，而中转站用免费证书的非常多。
- 于是校验开着的时候，Chromium 会判定证书链不可信、在建连阶段直接拒掉，
  报 `net::ERR_CERT_AUTHORITY_INVALID`。这**不是中转站配错了，是机器老了**，
  用户换多少个中转站都没用 —— 只会得出「这软件连不上网」的结论。

所以默认「能连上优先」，同时留一个开关：证书链正常的环境
（新装的 Win10/11、或打过补丁的 Win7）可以勾上，换回这道防护。
不校验的代价是**无法确认对面就是那个中转站**，密钥与对话内容可能被
中间人截获（公共 WiFi、校园网透明代理），文案里写清楚了这一点。

证书类报错仍会被翻译成中文，并把「去哪里开/关这一项」写出来 ——
报错不指向开关的话，这个开关等于不存在。

两条实现上的约束（改之前先看 `src/main/tls.ts`）：

- **不校验就是整个会话都不校验**（`callback(0)`），不做「只放行中转站域名」
  那种收窄。收窄看着更克制，但请求是 `redirect: 'follow'`，
  中转站完全可能 302 到别的域名，那一跳仍会被拒 —— 在 Win7 上等于没修好。
  影响面是可控的：这个 session 只承载 AI 请求，渲染层走本地文件，
  预览服务绑 127.0.0.1 的 http，MCP 是独立子进程。
- **落盘的值要在启动时就生效**，且缺省必须是「关」。
  `config.ts` 里必须写 `input.verifyTls === true`：老配置没有这个字段，
  写成 `!== false` 会让 `undefined` 变成 true，等于给老用户
  **升级之后静默打开校验** —— 在 Win7 上表现为「升级前能用，升级后连不上」。

### 输入片段（`!` + Tab）

在编辑器里行首敲 `!` 再按 Tab，展开完整 HTML5 骨架，光标停在 `<body>` 里。
`css` / `js` / `md` / `json` 同理。

**与「新建文件套模板」共用同一份数据**（`file-templates.ts`）——
各写一份的话，新建出来的 index.html 与敲 `!` 展开的会不一样，
而这种不一致极难发现（要同时用两种方式各建一次才看得出来）。

`!` 是常用标点，所以只在**行首**才触发 —— 写 `Hello!` 或 `a !== b` 时不会弹。

### 本机开发环境探测

「帮助 → 运行环境体检」里会列出探测到的 python / node / git 等，
**这些信息也会随每次提问一起告诉 AI**，它就能直接选对解释器，
不用靠试错（先 `python hello.py` 失败、再 `node hello.js` 再失败 ——
每一次都是一轮完整的对话往返）。
