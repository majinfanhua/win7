# win7-ai-editor

面向教学场景的 AI 代码编辑器，分发为 **Windows 免安装版**，覆盖 **Windows 7 SP1 ~ Windows 10**（32/64 位）。

## 关键约束

| 项 | 取值 | 原因 |
|---|---|---|
| Electron | **22.3.27**（锁定） | 22.x 是最后一个支持 Win7 的版本，23 起要求 Win10 1809+ |
| 渲染目标 | Chrome 108 | Electron 22 内置 Chromium |
| 主进程目标 | Node 16 | Electron 22 内置 Node 16.17.1（无全局 fetch） |
| 原生模块 | **禁止引入** | ABI 110，预编译包不可用 |

## 打包方式

**只通过 GitHub Actions 打包**，开发环境不做 Windows 打包（`npm run dist:win` 会直接拒绝执行）。

产物（免安装 zip，x64 + ia32）：

```
AIEditor-<version>-win7-win10-x64.zip
AIEditor-<version>-win7-win10-ia32.zip
```

> Windows 版本不是打包维度。同一份包在 Win7 SP1 / Win8 / Win10 上都能跑，
> 系统差异在启动时自适应（Win7/8 走软件渲染，Win10 走硬件加速）。

### 产物从哪拿

| 位置 | 在哪 | 说明 |
|---|---|---|
| **Releases 页**（推荐）| 仓库 → Releases | `latest` 是 main 的滚动构建（prerelease）；推 `v*` tag 生成正式 Release |
| Artifacts | 工作流**运行页**（不是任务日志页）底部 | 带自检报告，默认 90 天后过期 |

> 两个常见困惑：
> 1. **任务日志页看不到 Artifacts**，必须点进工作流的运行页，在最下方。
> 2. 构建成功**不会自动产生 Release**（除非推 tag），这是刻意的：Release 只从 tag 或滚动 `latest` 来。

## 本地开发

```bash
npm ci
npm run dev        # 开发模式（Vite HMR）
npm run typecheck  # 类型检查（主进程 + 渲染层，两份 tsconfig）
npm run build      # 构建（会先跑 check:node16 与 check:watch）
npm run smoke      # 无头启动自检（Linux 需 xvfb，其他平台会直接弹窗口）
npm run check:watch # 单独校验文件监视的时序（纯 Node，不用开窗口）

# 自检支持追加参数，用于在本地复现 CI 里那几次不同配置的运行
npm run smoke -- --capability-profile=win7   # 强制 Win7 工具能力档
npm run smoke -- --software --self-test-out=t.json
```

> 开发态的用户数据目录是 **`AIEditor-dev`**，与打包版的 `AIEditor` 分开。
> 这样 `npm run dev` 不会和本机已解压的打包版抢单实例锁，也不会写坏真实配置。
> 启动日志会打印实际目录。

### dev server

| 项 | 值 |
|---|---|
| 地址 | `http://0.0.0.0:5173/`（绑所有网卡，局域网可访问）|
| 端口 | `5173`；`strictPort` 打开，被占时直接报错，不会悄悄换端口 |

只想本机访问：把 `electron.vite.config.ts` 里 `renderer.server.host` 改回 `'127.0.0.1'`。

**不要用普通浏览器直接打开 5173** —— 渲染进程依赖 preload 注入的 `window.api`，
缺了它 `App.tsx` 会直接报错白屏，5173 只能由 Electron 加载。

Linux 容器 / root 环境下 Electron 起不来（`chrome-sandbox` 非 setuid-root），改用
`npx electron-vite dev --noSandbox`。

## AI 工具能力（按系统分层）

AI 能对文件做什么，由**两层**共同决定：

| 层 | 来源 | 说明 |
|---|---|---|
| 设置 | `config.capability`，在「设置 → 工具能力」里改 | 你**愿意**放开到哪（自动 / 保守 / 全开） |
| 探测 | 启动时读系统版本与解释器，只读 | 这台机器**实际**能做到哪 |

最终生效 = 设置上限 ∩ 本机探测 − 逐个关掉的项。改完保存立即生效，不用重启。

跨系统的文件工具（读取 / 写入 / 替换一处 / 替换多处 / 列出目录 / 撤销修改）
在所有支持的系统上都能用；依赖命令执行的工具（执行命令 / 后台任务）
只在 Windows 10 及以上启用 —— Win7 裸机只有 `cmd.exe`，PowerShell 需装 WMF 升级才有 5.1。

所以：**Win7 上是 6 个工具，Windows 10 及以上是 10 个**。同一份包，同一套代码，
差的是探测结果。Win11 走的是同一条路径（同样会启用），但 Win11 不在承诺支持范围内
—— 详见 `docs/技术框架方案.md` 的支持矩阵。

门控作用在**发给模型的工具表**上，而不是界面上的按钮显隐：
模型看不到的工具就不会去调，省掉一整轮白跑的 token。

`--capability-profile=<tier>` 可以强制按某个系统等级计算能力集，
用于测试 Win7 那条降级分支 —— CI runner 是 Server 2022，探测结果永远是 win10，
不这样跑就永远测不到。CI 会跑两次自检（默认档 + Win7 档）并断言后者是前者的子集。

### 执行命令类工具（仅 Windows 10 及以上）

四个：`执行命令`、`后台任务`、`查询任务`、`终止任务`。它们的存在意义是
「AI 能自己跑一下看看」，而不是「把终端搬进编辑器」。几个关键取舍：

- **跑的是 PowerShell，不是 Bash**。工具名叫 `RunCommand` 而不是 `Bash`：
  Win7 裸机上没有可用的 PowerShell，真 Bash 要 WSL 而学生机不能假定有。
  叫 `Bash` 会让人以为 `&&`、`$VAR`、管道都能照搬，实际上不是。
- **脚本用 `-EncodedCommand` 传**（UTF-16LE 的 base64），不用 `-Command`。
  Node 转义参数里的引号走的是 C 运行时那套规则，PowerShell 有自己一套，
  引号 / `$` / 反引号混在一起时两边对不上，会出现「在终端里能跑、在这里跑不了」。
- **输出编码在脚本前先切成 UTF-8**。中文 Windows 的默认输出代码页是 936（GBK），
  Node 按 UTF-8 解字节就是满屏乱码，学生会以为是命令跑错了。
  收字节时用 `StringDecoder` 而不是 `chunk.toString()`，否则一个汉字被切在两个 chunk 之间就变成问号。
- **超时默认 30 秒，上限 5 分钟**，到点用 `taskkill /PID <pid> /T /F` 杀**整棵进程树**。
  顺序不能反：先 `child.kill()` 把 powershell 干掉的话，它启动的 `python.exe`
  就找不到爹了，`/T` 遍历不到，反而留下一堆占着端口与 CPU 的孤儿进程。
- **长命令走 `jobRun`**，立刻返回任务号，之后用 `jobPoll` 查。
  任务只活在主进程内存里（不落盘），并发上限 4 个，单个硬上限 30 分钟，
  关窗口时全部终止 —— 否则学生关掉编辑器后 `node.exe` 会继续占着端口，
  下次启动就变成「端口被占用」这种完全查不到原因的故障。
- **工作目录默认项目根目录，且必须在项目内**。命令本身当然能 `cd ..`，
  但默认落在项目里能让绝大多数情况不需额外参数。
- **输出有上限**（单次 6 万字符，回灌给模型前再裁到 1.2 万，留头尾）。
  跑一次构建可能吐几十万行，全塞进上下文既烧 token 也淹掉真正的报错。

**两件在真机上才能验的事**（见 `docs/多系统-测试清单.md`）：中文输出的编码是否正常、
杀软会不会拦子进程（校园机器上这一条会表现为「偶发失败」，很难排查）。

## 界面结构

两栏：

| 栏 | 管什么 | 关键文件 |
|---|---|---|
| 左侧栏 | 上半：产品标识 / 新对话·Skills·MCP / 工作空间 / 最近会话<br>下半：当前项目的文件树（可折叠） | `components/Sidebar.tsx`、`components/FileTree.tsx` |
| 内容区 | 横向分成**编辑器（左）**与**对话（右）**，中间是竖向可拖拽分割条 | `components/EditorPane.tsx`、`components/AiPanel.tsx` |

### 为什么是「编辑器在左、对话在右」

和 Cursor / Windsurf 一致：写代码时视线在左边，提问是**间歇动作**，放右栏不挡住代码。
反过来把对话放左边，每次提问都要把视线拉回最左侧、代码被推到右边，反而更累。

对话栏可以整体收起（顶栏那个面板按钮），收起后编辑器接管全部宽度。
收起用的是 `data-chat-closed` 属性 + `display:none`，不是条件渲染 ——
保留 DOM 才能留住输入草稿与滚动位置。

### 文件树为什么并进左侧栏

它和「工作区 / 最近会话」本来就是一类的：都是「我在哪个项目、项目里有什么」。
放同一栏符合直觉，也给对话栏腾出了完整的右侧空间。
左侧栏由此分成两个独立滚动的区段：

- `.sidenav-top` —— 动作键与两个列表，内容长了只滚这里
- `.nav-group-tree` —— 文件树，`flex:1 + min-height:0` 吃掉剩余高度、自己滚

这两段必须分开滚。以前整个侧栏是一块 `overflow-y:auto`，
文件树嵌进来后就会出现「文件多了把侧栏整个推长，而文件树自己那一段反而没滚动条」。

### 分割条的一个坑

竖向分割条**不能占布局宽度**。两侧宽度加起来已经是 100%
（`--split` 与 `1 - --split`），分割条如果再要 9px，它就会因为「没地方放」
被挤到容器最右边缘 —— 实测错位 454px。

解法：`width: 9px` 配 `margin: 0 -4.5px`，正负抵消后布局宽度为 0，
9px 的命中区横跨在接缝上，视觉上仍是一条 1px 竖线。

另外 DOM 顺序也必须是「编辑器 → 分割条 → 对话」。放到最后同样会被挤到最右边，
位置是由顺序决定的，光靠 CSS 救不回来。

### AI 改完文件，编辑器必须立刻看到

这是 AI 编辑器里最不能缺的一环。原来的实现里，AI 调用工具改了磁盘上的文件，
编辑器却还在显示内存里的旧副本 —— 学生看到「AI 说改好了，但代码没变」，
这种不一致足以让人完全失去信任。

修复分两半：

**主进程：`main/watcher.ts`**

用原生 `fs.watch(root, { recursive: true })` 监视工作区，改动推给渲染层。

- **不引 chokidar**：它在 Win7 上会退回轮询模式（`fs.watchFile`），50ms 一轮地 stat
  整棵目录树，机械盘上直接变成 100% 占用。`fs.watch` 在 Windows 上底层是
  `ReadDirectoryChangesW`，是真正的内核事件，零轮询开销 —— 对教室里的老机器
  这是唯一可接受的选择。
- **工具写入要标记来源**。`file-tools.ts` 在写盘前后调 `markToolWrite()`，
  事件里就带上 `origin: 'ai'`；否则编辑器分不清「AI 改的」与「别人改的」，
  只能一律弹提示，那就太吵了。
- **debounce 120ms**。一次写入通常触发多次事件（write + rename），需要合并。

**渲染层：`store.handleFileChanged()`**

按三种情况分别处理，因为「文件变了」在三处的正确反应完全不同：

| 情况 | 处理 |
|---|---|
| 没在编辑器打开 | 只记日志，不打扰 |
| 打开了、本地无未保存改动 | 静默重载，AI 改的标上「AI 修改」 |
| 打开了、本地有未保存改动 | **绝不覆盖**，只警告，由学生决定 |

第三条是关键：AI 改了文件而学生手里有没保存的编辑时，把磁盘内容盖上去
等于把学生刚写的代码删了。宁可保留冲突让学生选。

### 撤销 AI 的改动

`tools/snapshot.ts` 在每次写盘前存一份原文（跨重启保留）。两个入口：

- **编辑器内的横幅**：AI 改过的文件顶上会显示「AI 修改了 xxx」+「撤销这次修改」/「保留」
- **设置 → 修改历史**：列出当前项目所有可撤销记录（文件名 / 时间 / 来源 / 行数差）

手动保存（Ctrl+S）也会记一条快照。不记的话会有个难查的问题：
AI 改完 → 学生自己又存了一次 → 按撤销时退到 AI 改之前，学生刚写的东西凭空消失。

`listSnapshots()` **只返回当前工作区内的记录**。撤销记录是跨项目累积的，
把别的项目的文件列出来，学生按一下会改到另一个项目的代码，这在教学场景里很难解释。

### 会话恢复

重启后自动恢复上次打开的标签、激活项、每个文件的光标位置、以及分割比例，
存在 `config.json` 的 `editorSession` 里。

三个细节：

- **只存路径，不存内容**。内容是磁盘上的真实状态，缓存一份下来就会和磁盘分叉，
  下次启动反而显示旧代码。
- **落盘前过滤已不存在的路径**（`editorSessionSet`）。工作区可能在关机期间被移动或删除，
  照单全开会在界面上弹一排「打开失败」。
- **防抖 600ms + 关窗前 flush**。开关标签、移光标都会触发保存，太频繁；
  但直接关窗会丢掉最后几百毫秒 —— 而「刚打开一个文件就关掉应用」恰好很常见。

### 分割条的拖拽实现

左右可拖拽，键盘也能调（聚焦后用 ←/→ 步进 2%，Shift 加速到 10%，Home/End 到两端），
双击复位到 62%。顶栏还有「改 / 均 / 问」三个预设按钮一键到位。

实现在 `hooks/useSplitter.ts`（支持两个方向，用 `axis` 参数切换），两个关键点：

- **拖动期间不 setState**。`pointermove` 能到 60~120Hz，每帧触发 React 重渲染会让
  Monaco 明显卡顿。所以拖动时只改 `documentElement` 上的 `--split` CSS 变量
  （不触发渲染），松手才提交一次状态。
- **用 Pointer Events + `setPointerCapture`**，不是 mouse 事件。这让指针跑到分割条
  外面（甚至窗口外）仍能继续收事件 —— 鼠标拖拽最容易在这里断掉。触摸也走同一条路径。

`--split` 的语义是**左侧（编辑器）占内容区的比例**。比例只存比值不存像素，
窗口缩放时按比例跟随；`editorSessionSet` 落盘时夹到 0.28~0.78，
防止某个配置文件被手改成 0 之后编辑器彻底看不见。

### 空态（欢迎页）

火箭图标 + 「{时段}好，今天想从哪里开始？」+ 三张横排入口卡（解读项目 / 修复问题 / 头脑风暴），
下方是输入框与工具栏。

- **三张卡无论是否配置模型都显示**。它们本身就是「这个软件能干什么」的说明书，
  没配置时恰好是最需要它的时候；没配置时点击引导到设置页，而不是把卡片藏起来。
- **问候语按当前时段变**（早上好 / 下午好 / 晚上好），固定一句「你好」会显得很假。
- 输入框下方工具栏里的图片 / 附件 / 截图 / 配色 / Git 入口**置灰并标注「暂未支持」**。
  保留占位是为了让工具栏宽度稳定，以后接上功能时不会把右侧发送键挤走。
  点了没反应比明确说「还没做」更让人困惑。

### 右侧右键菜单

预览文件 / 新建文件 / 新建文件夹 / 重命名 / 删除 / 显示隐藏文件 /
复制路径 / 打开所在目录 / 插入引用 / 刷新。

几个刻意的取舍：

- **预览文件**只对 `.html` 生效，走系统浏览器。实现上会起一个只绑 `127.0.0.1` 的临时静态服务
  把工作区当根目录 —— 直接给浏览器 `file://` 的话，`./src/main.js` 这类相对路径会被
  同源策略拦掉，学生看到的是「没样式也没反应」的页面。
- **删除**走系统回收站（`shell.trashItem`），不是 `rm`。误删能捞回来，这在教学场景里很重要。
- **显示隐藏文件**是开关，写进 `config.explorer.showHidden`。`node_modules` / `.git` 之类
  无论开关如何都不列 —— 一次 `readdir` 几万条，Win7 机械盘上会直接卡死。
- **插入引用**不把路径拼进输入框文本，而是挂成输入框上方的胶囊。
  拼进输入框的话，学生想删掉一个引用得手动选中一大段路径。
- 不适用的项（比如没选中文件时的「重命名」）**置灰而不是隐藏**，菜单位置稳定才好找。

### 会话记录：索引与正文分开放

| 位置 | 存什么 | 上限 |
|---|---|---|
| `config.json` → `recentSessions` | 索引：id / 标题 / 工作区 / 时间 / 条数 | 20 条 |
| `userData/sessions/<id>.json` | 正文：消息列表 | 200 条 / 单条 20 万字符 |

分开的理由：左侧列表每次启动都要整份读，索引必须小；正文只有点开某条会话时才读，
几 MB 也无所谓。

**正文是整份覆写，不是追加**。写 `.tmp` 再 `rename` —— `rename` 在同一文件系统内是原子的，
所以要么读到旧的完整文件，要么读到新的完整文件，不存在中间态。
直接 `writeFile` 覆盖的话，写到一半断电就会留下截断的 JSON；
而 jsonl 追加写到一半会留下半行坏数据，还得写恢复逻辑。

**落盘有 400ms 防抖**，而且只在「一轮回答结束」和「用户主动停止」两个时刻触发。
流式期间每来一个 token 就写盘的话，一轮回答要写几百次几 MB 的文件。

**流式的中间态不落盘**：`items` 是渲染态（带 usage / tools），`messages` 是持久化态
（只有 role / text / at）。重建历史时不会带出上一轮的 token 数 —— 那些数字显示在旧气泡上
会让人误以为是当前的。

`工作空间` 与 `会话` 都落在 `config.json`，关掉应用再打开还在。
