### 压缩怎么做的

到窗口 80% 时，把**较早的**对话总结成一段「交接说明」插回最前面，
保留最近 2 轮原文：

```
[system] [摘要] [最近 2 轮...] [这一轮的新提问]
```

- 判定（`compaction-policy.ts`）与执行（`compaction.ts`）**分家**：
  判定是纯函数，护栏能直接钉；执行要调模型，必须在能拿到 API Key 的主进程
- 与**归档总结**的提示词各写一份：归档问「我们讨论过什么」，
  压缩问「任务进行到哪一步、还剩什么」—— 用归档那段做压缩，
  模型拿到的是没用的会议纪要
- 失败**不阻断**：降级为按完整历史发送（宁可报一次可读的超预算，也不能发不出话）

### 这一轮踩到/修掉的三个真 bug（都完全静默）

1. **渲染层会把摘要丢掉**。历史归渲染层所有、每轮整份发过来；
   而 `syncFromItems` 等处硬编码了 `role === 'user' || 'assistant'`，
   摘要（system）会被过滤掉 → 「看着省了 token，下一轮又变回完整历史」，
   每轮重复花一次总结的钱，**不报错**。
   修法：判定收成**一处** `isConversationRole`，并加护栏钉住。
2. **系统提示词注入会把摘要顶掉**。注入用
   `findIndex(m => m.role === 'system')` 找位置，而摘要也是 system ——
   摘要被**整个替换**成系统提示词，AI 突然失忆。请求照常成功，只是答非所问。
   修法：`injectSystemPrompt` 用 `SUMMARY_MARKER` 把摘要排除在外。
3. **重复压缩会逐层丢失更早的上下文**。第二次压缩时，上一次的摘要
   在 `head` 里；`toSummarizeInput` 只收 user/assistant、重组时又把它替换掉 ——
   最早那段对话的信息**彻底消失**，每压一次再丢一层。
   表现是「聊得越久，AI 越不记得开头说过什么」。
   修法：总结输入保留已有摘要（映射成 user + 标注），位置不变以保住缓存前缀。

第 2、3 条是**写完之后复查**发现的，不在最初的计划里 —— 都属于
「摘要与系统提示词都是 system 角色、代码分不清」，所以一并收敛到
`injectSystemPrompt` / `rebuildAfterCompaction`，并加断言禁止再出现
裸的 `findIndex((m) => m.role === 'system')`。

### `/` 命令的几条设计决定

- **渲染层直接执行**，不发请求、不花 token
- 只在**行首或空白之后**触发：`3/4`、`/usr/local`、`https://…` 不算
- 「当前用不了」的命令（如空对话时的 `/compact`）**置灰但仍显示**，
  藏起来会让学生以为命令名记错了
- `error` 与新增的 `notice` 角色**不发模型、不落盘**：
  以前只区分 user/assistant，现在必须明确「哪些算对话内容」，
  否则 `/help` 的输出会被当成历史发出去、还会写进会话文件

### 阈值公式换了（护栏断言同步改过）

`窗口 × 比例` 取代 `窗口 − 输出预留 × 因子`。换的直接理由：
旧公式在 8k 小窗口上算出负数，只能靠下限 1024 兜住 ——
而 1024 在 8k 窗口上意味着「输入刚到 1k 就要压缩」，
小窗口模型的对话根本用不起来。

`scripts/check-context-budget.mjs` 里那些钉住具体数字的断言
（`103424` / `108339`）已同步改成新公式的期望值，并**补了切分边界的用例**
（`splitForCompaction`：只能在 user 边界切、轮数不够不压、空数组安全）。

**验证情况**：`npm run build` 全绿（19 道护栏 + electron-vite 构建），
两份 tsconfig 的 `tsc --noEmit` 通过。

**默认值为什么是关的**（第一版写反了，留个记录）：

**新增的三道护栏**（都进了 `npm run build` 与 CI）：

- `scripts/check-idle-timeout.mjs` —— 超时必须仍是停顿判定。
  光把常量改大不算修好：如果 SSE 的 `data` 回调里没有 `progress()`，
  那仍然是一个「每轮固定 N 分钟」的定时炸弹。所以同时断言阈值、重置点、停表点。
- `scripts/check-chat-text.mjs` —— 换行清理的三条规则
  （只压连续空行 / 只动行尾 / 幂等）。错了只是空白多寡的差别，界面上很难看出来。
- `scripts/check-zip-wrap.mjs` —— zip 字节级改写的 16 项断言。
  测试用的 zip 由脚本自己按规范拼出来（只用 `node:zlib`），
  所以不依赖 electron-builder、不依赖 7za、也不依赖产物已存在，**打包前就能跑**。

**这一轮踩的坑（重要）**：

zip 套文件夹的第一版实现调外部 `7za rn` 并解析它的**文本输出**拿文件名，
**在 CI 上挂了**。两个原因都在开发机上测不到：

1. 外部 7za 的版本行为 —— 开发机是 Linux p7zip **16.02**，
   runner 是 Windows 7-Zip **21.07**，不是同一个程序。
   **本项目只出 Windows 包，拿 Linux 的 7za 验证等于没验证。**
2. 7za 按**控制台代码页**输出文件名，英文 runner 表示不了「使用说明.txt」，
   读回来是乱码，再喂回 `rn` 就匹配不到 —— **而匹配不到时退出码仍是 0**，
   静默什么都没做。

现在改成纯 Node 直接改 zip 字节：零外部进程、不解析任何文本输出，
两边行为完全一致。**以后凡是「给 Windows 用的东西」，别拿 Linux 的同名工具
当验证依据** —— 这条对打包链路尤其重要。

**这一轮没在真机上验过的**：
- ⬜ zip 套文件夹在本地用**真实 Release 产物**验过（顶层 19 项 → 1 项、
  75 个条目的 CRC / 大小 / 压缩方法 / 时间戳 / UTF-8 标志位逐条一致、
  内容 SHA256 全等，并用 python zipfile 与 7za 两条独立路径复验）。
  现在实现是纯 Node、无平台差异，但**仍以 CI 那一步的实际结果为准**。
- ⬜ 停顿看门狗只做了静态断言与构建验证，**没有真的挂一个慢模型跑满 5 分钟**。
  想手工验：把 `STREAM_STALL_TIMEOUT_MS` 临时改成 10 秒，发一个长问题，
  看是不是「只要还在吐字就不超时」。

## 已知坑（改之前务必看一眼）

- **不要先 `child.kill()` 再 `taskkill`**。先杀 powershell 就找不到它的子进程了，`/T` 遍历不到，
  反而留下一堆占着端口与 CPU 的孤儿进程。正确顺序写在 `tools/exec.ts` 的注释里。
- **命令输出的编码**：中文 Windows 默认输出代码页是 936（GBK）。
  脚本前必须 `[Console]::OutputEncoding = UTF8`，收字节必须用 `StringDecoder`——
  一个汉字 3 字节，会被切在两个 chunk 之间，`chunk.toString()` 会各自解出半个字符。
- **传脚本用 `-EncodedCommand`，不用 `-Command`**。Node 的引号转义是 C 运行时那套，
  PowerShell 是另一套，引号 / `$` / 反引号混在一起时两边对不上，会出现「在终端能跑、在这里跑不了」。
- **Electron 里 `window.prompt` 不可用**。不是「不弹框」，是调用直接抛错、返回 undefined ——
  所以代码写得再对也什么都不会发生。文件树的新建 / 重命名曾经全依赖它，
  表现就是「点新建文件夹能建（走系统对话框）、点新建文件没反应」。
  现在统一走 `components/InputDialog.tsx`。**`alert` / `confirm` 是可用的，只有 `prompt` 被移除**，
  别因为这次踩坑把 confirm 也一起废掉。
- **`config.ts` 的 `normalize()` 是白名单式的**。新增顶层 section 不加进去，
  每次加载会被静默吞掉（设置里改完、重启就没了，而且不报错）。这是最容易漏的一处。
  `explorer` 段现在走 `normalizeExplorer()`，里面 `sortBy` 是枚举白名单式的 ——
  增删排序方式时两处都要改。
  **同理写 `prompt` 的修正时注意**：`pushLog` 里的 `time: ''` 是刻意的，
  时间戳由 store 统一补，不要传 `new Date()`。
- **`setConfig(patch)` 顶层是浅合并**。传 `{ capability: { mode: 'full' } }` 会把整个 `capability` 替掉。
- **分割条不能占布局宽度**。两侧宽度加起来已经是 100%，分割条再要 9px 会被挤到容器最右边缘（实测错位 454px）。
  解法是 `width:9px + margin:0 -4.5px`；而且 DOM 顺序必须是「编辑器 → 分割条 → 对话」，
  位置由顺序决定，光靠 CSS 救不回来。
- **文件树与侧栏要分两段滚**。`overflow-y:auto` 放在整个侧栏上，会出现「文件多了把侧栏整个推长，
  而文件树自己那一段反而没滚动条」。
- **AI 改了文件、学生手里有未保存改动时绝不覆盖**。只警告，由学生决定——
  把磁盘内容盖上去等于把学生刚写的代码删了。
  ⚠️ **配套前提：那条警告得有地方显示**。本轮之前它只进 `store.logs`，
  而渲染层从来没渲染过 logs —— 警告等于没发。现在靠 `LogDrawer` 承接。
  **再动日志链路时记得这条**：一个没人看的警告比不警告更糟，
  因为它让「已经处理好了」变成一句空话。
- **`closeTab` 与 `closeTabChecked` 不能合并**。前者被「文件已删除」「重命名」
  这些非用户主动路径调用，那些路径上弹「要保存吗」是纯干扰；
  后者才是「用户点了 ×」用的。同理 `forgetSubtrees` 必须挂在
  **删 / 改名 / 移动目录**三条路径上，漏一条就出幽灵文件。
- **单向推送的通道两端都要有人**。`evtLog`（`onLog`）与 `sendMenu` 的动作
  都踩过「主进程发了、渲染层没接」——表现是点了没反应，且不报错。
  新增任何 `evt*` 或菜单动作时，顺手确认对面有消费者。
- **工具写入要标记来源**（`markToolWrite`），否则编辑器分不清「AI 改的」与「别人改的」，只能一律弹提示。
- **文件监视不引 chokidar**。它在 Win7 上会退回轮询模式，50ms 一轮 stat 整棵树，
  机械盘上直接 100% 占用。用原生 `fs.watch`（Windows 上底层是 `ReadDirectoryChangesW`）。
- **样式文件的层叠顺序是契约**，写在 `styles/index.css`。`responsive.css` 必须最后
  （窄屏要覆盖各组件写死的宽度），`editor.css` 必须在所有拆分文件之后
  （`.editor-host` / `.crumb-model` 在前面有基础定义）。`base.css` 最前。
  `logs.css` 必须在 `dormant.css` 之后（那份里已有一个 `.logs`）。
  调顺序不会报错，只会静默地让覆盖失效 —— 而且只在窄屏 / 空态这种边角下看得出来。
- **`SPLIT_MIN` / `SPLIT_MAX` 只有一份**（`shared/types.ts`），界面与落盘都读它。
  曾经界面写 0.28/0.78、落盘夹 0.2/0.9，表现为「拖到中间地带时，
  当次会话被夹住、重启后又原样读回来」——同一次拖动两种行为。
  **别再把字面量写回 `App.tsx`**。
- **中英两个 `parentOf` 只留一个**。现在统一用 `explorer-helpers` 的 `parentDirOf`
  （useAppStore 里 `as parentOf` 重命名导入）。历史上两份实现并存过，
  改其中一份不会报错，只会在某个调用点上算出不同的父目录。
